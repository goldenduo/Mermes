# 伪终端界面显示与输入控制逻辑分析

本文档分析了 Termux-app 项目中伪终端（Terminal）的界面显示机制与输入控制逻辑，并总结了在进行 UI 开发时的关键注意点。

## 一、 界面显示逻辑 (Display Logic)

伪终端的界面渲染遵循 MVC 的设计思想，通过分离模型（终端状态）与视图（屏幕绘制）来实现高效刷新。

1. **TerminalEmulator (模型层 - 终端模拟器)**
   - 维护抽象的终端状态。它内部包含 `TerminalBuffer`，负责存储多行文本（`TerminalRow`），包括字符的 Unicode 码点和对应的样式（颜色、加粗、下划线等）。
   - 处理 ANSI 转义序列并更新屏幕缓冲区及光标位置。

2. **TerminalView (视图层 - Android View)**
   - 继承自 Android 的 `View`，负责处理系统布局及测量事件（`onSizeChanged`）。
   - 每次屏幕需要更新时（如接收到新的终端输出，或光标闪烁），触发 `invalidate()` 重新绘制。
   - `onDraw(Canvas canvas)` 是渲染入口，它本身不执行具体的字符绘制，而是委托给 `TerminalRenderer`。

3. **TerminalRenderer (渲染引擎)**
   - 负责实际的 `Canvas` 绘制操作。在初始化时计算字体度量信息（`mFontWidth`，`mFontLineSpacing` 等）。
   - 在 `render()` 方法中，它遍历 `TerminalEmulator` 中当前可见的行，按列读取字符。
   - **优化渲染 (Text Run)**：为了提升性能，渲染器会将具有相同样式（前景色、背景色、加粗等）且连续的字符合并为一个“绘制批次 (Text Run)”，然后统一调用 `canvas.drawTextRun()` 绘制。
   - 同时负责绘制光标位置以及高亮选中的文本。

## 二、 输入控制逻辑 (Input Logic)

输入控制主要涉及 Android 触摸及按键事件的捕获、转义处理以及向底层伪终端进程的管道传输。

1. **事件捕获 (TerminalView)**
   - **键盘输入**：通过重写 `onKeyDown`、`onKeyUp` 以及 `onKeyPreIme` 捕获物理和虚拟键盘输入。对于组合键（Ctrl, Alt/Esc, Shift, Fn），`TerminalView` 会根据按键状态和字符生成相应的行为。
   - **触摸/手势**：`onTouchEvent` 捕获滑动手势进行页面滚动，或者长按唤出上下文菜单（复制/粘贴）。
   - **输入法连接**：对软键盘而言，字符输入可能跳过标准的 KeyDown 事件。

2. **字符与转义转换 (KeyHandler / TerminalView)**
   - 常规输入：调用 `TerminalView.inputCodePoint()` 获取输入的 Unicode 码点。如果当前处于组合键状态（例如按下了 Ctrl），则将输入字符转换为对应的控制字符（如 `Ctrl+C` 转换为 `0x03`）。
   - 控制键映射：回车、退格、方向键等硬件或软件控制按键，通过 `KeyHandler.getCode()` 被转换成标准的终端转义序列（例如左方向键转成 `\033[D`）。

3. **数据传输 (TerminalSession)**
   - `TerminalView` 将处理后的字符串、字符或字节数组传递给当前绑定的 `TerminalSession`。
   - `TerminalSession` 调用 `mTermSession.write(...)` 方法，将数据压入进程 IO 队列 (`mTerminalToProcessIOQueue`)。
   - 独立的后台 I/O 线程循环读取该队列，并将字节流写入到伪终端文件描述符 (`termOut.write()`) 中，从而发送给运行在后台的 Bash 或 Zsh 进程。

## 三、 UI 注意点 (UI Considerations)

在针对此类终端界面进行二次开发或定制时，需要特别注意以下几点：

1. **中英文支持与多语言切换 (Localization)**
   - **提示与菜单**：`TerminalView` 相关的长按上下文菜单（如 Copy、Paste、More）以及自动填充的 UI 提示，不应硬编码为英文。需使用 Android 资源文件（`res/values/strings.xml` 和 `res/values-zh/strings.xml`）来支持动态的中英文切换机制。
   
2. **字符宽度与排版 (双宽字符)**
   - 终端严重依赖等宽字体 (Monospace)。但在混排中英文时，中文字符（全角）的宽度应为英文字符（半角）的两倍。
   - `TerminalRenderer` 使用 `WcWidth.width(codePoint)` 来计算字符占据的终端列数。中文字符宽度返回 2。
   - 必须处理 **“字体宽度不匹配” (Font Width Mismatch)**：某些 Android 系统字体可能未严格遵守 `中文宽度 = 2 * 英文宽度` 的规范。`TerminalRenderer` 中的检测逻辑会在度量宽度与预期列宽不符时，对 `Canvas` 进行横向拉伸/缩放 (Scale)，以保证严格的网格对齐，这是中文正常显示的基石。

3. **软键盘与输入法兼容性 (IME Compatibility)**
   - 不同的 Android 虚拟键盘（Gboard, Hacker's Keyboard, 搜狗输入法）行为各异。有些通过触发 KeyEvent 传递字符，有些直接调用 `commitText()`。在扩展输入功能时，要全面测试主流输入法的输入劫持行为。

4. **文本选择与坐标转换 (Text Selection)**
   - 文本选择需要拖拽两个手柄（Handle）。UI 层必须准确处理屏幕像素坐标 `(x, y)` 与终端行列坐标 `(row, col)` 之间的转换。考虑到行距 (`mFontLineSpacing`) 和字体宽度 (`mFontWidth`)，这部分对触摸滑动的平滑度和边界判断要求极高。

5. **渲染性能与电池消耗**
   - 避免无效的 `invalidate()` 调用。光标闪烁通过 `Runnable` 定时触发局部重绘，若界面不可见应立刻停止该定时器（见 `stopTerminalCursorBlinker`），防止后台耗电。

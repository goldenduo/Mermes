# common需求

## 功能概述
`common` 模块是一个通用的 AAR (Android Archive) 基础库模块，为整个 Mermes 项目中的所有 Android 模块（如 `core` 和 `terminal` 等）提供底层公共能力，核心功能是全局日志管理（Logger）与崩溃监听（Crash Handler）。

## 功能点

### 1. 全局 Crash 日志监听回调
- **功能描述**: 允许注册自定义的崩溃监听器，当应用发生未捕获异常时触发回调（如用于上报崩溃日志、展示特定 UI 或保存崩溃到特定文件）。
- **默认行为**: 默认使用系统默认的 `Thread.UncaughtExceptionHandler` 进行处理。
- **重置功能**: 提供方法可以随时注销自定义回调，恢复到系统默认处理器。

### 2. 统一日志级别控制与遮蔽
- **功能描述**: 统一控制整个应用内的日志级别。提供 `VERBOSE`, `DEBUG`, `INFO`, `WARN`, `ERROR` 五级日志输出控制。
- **级别管理**: 可以动态设置当前全局最低输出级别（如 DEBUG 版本输出 `VERBOSE` 及以上，Release 版本输出 `INFO` 及以上）。
- **发布级别日志（Release Logs）控制**: 当处于发布模式（Release）或设置了遮蔽标志时，自动对日志内容进行安全过滤，仅输出抽象的非实现细节概要信息，隐去具体的敏感路径、动态参数、底层库函数及数据结构实现，确保安全防泄漏。

### 3. 基础依赖规范
- **统一底层依赖**: 作为 `core` 和 `terminal` 等所有 Android 相关模块的强依赖，作为基础功能支撑。
- **强制使用规约**: 所有模块废弃直接使用 Android 标准 `android.util.Log` 的做法，统一采用 `common` 模块提供的 `MermesLog`。

## 非功能性需求
- **无感延迟**: 日志包装和 Crash 捕获必须具备极高的性能，不可阻塞主线程。
- **业务无关**: 作为通用的独立 AAR，完全不包含具体业务逻辑。
- **多语言（I18N）**: 崩溃日志或统一日志框架涉及用户界面或展示给用户的文案时，必须支持中英文切换。

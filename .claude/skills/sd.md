# sd (sync-docs)

将当前对话中讨论的需求、接口定义或代码修改点同步到项目文档中，并自动开始开发。

## 使用方式

用户输入 `/sd` 时触发。

## 执行流程

### 第一步：分析对话内容

从当前对话中提取以下信息：
- **需求**：用户描述的功能需求、业务逻辑、行为要求
- **接口**：API 接口定义、函数签名、数据结构、协议约定
- **修改点**：对现有代码的修改、优化、bug 修复等内容

### 第二步：确定模块名称

根据对话内容推断所属模块：
- 如果用户明确指定了模块名，使用用户指定的名称
- 否则根据对话内容自动推断（如：下载模块、转换模块、bootstrap 模块等）
- 模块名应简洁，使用中文或英文均可

### 第三步：同步到文档

根据内容类型选择目标文件：
- 需求类内容 → `docs/{模块名}需求.md`
- 接口类内容 → `docs/{模块名}接口.md`
- 如果两者都有，分别写入对应文件

**文档结构要求**：
- 内容必须保持结构化、层次清晰
- 使用标准的 Markdown 标题层级（# ## ###）
- 每个功能点/接口独立成节，便于单独修改
- 相关内容聚合在一起，形成完整的模块文档

**需求文档格式**：
```markdown
# {模块名}需求

## 功能概述

{模块整体功能描述}

## 功能点

### {功能点1标题}

{功能点1详细描述、实现要求、边界条件}

### {功能点2标题}

{功能点2详细描述}

## 非功能性需求

{性能、兼容性、安全等要求}
```

**接口文档格式**：
```markdown
# {模块名}接口

## 接口列表

### {接口1名称}

- 路径/签名：`{接口路径或函数签名}`
- 方法：`{GET/POST/函数}`
- 描述：{接口功能说明}

参数：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| xxx    | str  | 是   | xxx  |

返回值：
{返回值说明或示例}

### {接口2名称}

{同上格式}
```

**同步规则**：
- **新增**：文件不存在时，创建新文件并写入标准格式
- **追加**：文件已存在时，将新内容添加到对应章节末尾
- **修改**：文件中已有相同标题的章节时，更新该章节内容
- **合并**：相关功能点合并到同一章节下，保持文档整洁

### 第四步：确认并开始开发

同步完成后：
1. 显示同步结果（写入了哪些文件、新增/修改了哪些章节）
2. 询问用户是否开始开发
3. 如果用户确认，根据文档中的需求/接口自动开始实现代码

## 示例

用户：`/sd`

Claude 执行：
1. 分析当前对话，发现讨论了"bootstrap 下载脚本需要支持断点续传和并发下载"
2. 确定模块名为"bootstrap"
3. 读取 `docs/bootstrap需求.md`（已存在）
4. 找到"下载功能"章节，将新需求合并进去
5. 显示同步结果，询问是否开始开发
